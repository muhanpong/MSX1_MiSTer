# PCM 엔진을 128.86 MHz로 옮기는 재구성 계획

브랜치 `sdram128-study`. 배경: V9968 VRAM을 단일 SDRAM에 올리려면 SDRAM 컨트롤러를
85.909 MHz의 3/2배인 128.86 MHz에서 고정 슬롯(TDM)으로 돌려야 한다. PCM 엔진은 지금
clk_sdram(85.909 MHz)에서 돌고 SDRAM ch4를 쓰므로, 같은 128.86 MHz 도메인으로 옮긴다.

## 근거: 128.86 MHz 연구 빌드 (26d85bb, Quartus 17.0.2, Slow 1100mV 100C)

PLL 출력 0만 128.863620 MHz로 바꾼 빌드. clk_sdram setup 최악 -2.739 ns, TNS -601 ns,
도메인 내부 Fmax 95.25 MHz. 실패 끝점 782개 중

| 모듈 | 끝점 | 최악 |
|---|---|---|
| PCM 엔진 `u_moonsound/u_pcm` | 약 700 | -2.74 ns |
| SDRAM 컨트롤러 `sdram` | 76 | -1.43 ns |
| clk21m -> MoonSound | 6 | -0.21 ns |

SDC의 멀티사이클 N은 빨라진 클록 기준으로 읽혀 실제보다 빡빡하다. SDRAM 핀 IO 제약은
SDC에 없어 분석되지 않았다.

## 불변 조건

출력 샘플 스트림은 85.9 MHz 버전과 비트 단위로 같아야 한다. 스케줄만 1.5배로 늘리고
연산은 바꾸지 않는다. 각 단계는 85.9 MHz에서도 비트 일치를 먼저 확인한다.

## 1. 스케줄 파라미터화

| 상수 | 85.9 MHz | 128.86 MHz |
|---|---|---|
| `CYCLES_PER_FRAME` | 1948 | 2922 (44.1 kHz, 정확히 1.5배) |
| 슬롯 창 | 72 | 108 |
| `CPU_RESERVE` | 44 | 66 |

`CLK_HZ`에서 계산한다. `frame_cycle` 등 카운터 폭을 함께 넓힌다.

## 2. 실패 경로 리타이밍

슬롯은 순차 상태 머신이라 상태 하나를 쪼개는 비용은 1클록이다.

| 경로 | 대책 |
|---|---|
| `w_interp` -> MUL1 -> MUL2 (16x17, `>>>15`) | 곱셈마다 입력/출력 레지스터 두 상태 |
| 게인 (`32'sh8000 * vmul >>> vsh`) | 두 상태로 분리 또는 표 |
| `pcm_mlab24` 비동기 읽기 (약 22개) | 읽기 레지스터, LOAD에서 주소를 한 클록 먼저 |
| 캐시 태그/워드 MLAB + 21비트 비교 (CHIT) | 태그 읽기와 비교 분리 |
| `fm_r_mul` | 출력 레지스터 |

슬롯 고정 상태는 약 16클록에서 약 21클록이 된다.

## 3. SDRAM ch4: 쌍 단위 읽기

A샘플은 `wA0, wA0+1`, B샘플은 `wB0, wB0+1`로 연속 두 워드다. 쌍마다 버스트 2(32비트)
한 번으로 읽어 최악 4회를 2회로 줄인다. TDM 12클록 프레임에서 1회 약 19클록, 슬롯 최악
약 21 + 2 x 19 = 59 / 108클록. 응답은 32비트로 바꾸고 `SDRAM_RD_LAT`를 재정의한다.

## 4. 클록 도메인 경계

- CPU 레지스터 쓰기 clk21m -> 엔진: 1:6 정수비. 멀티사이클 재정의 또는 핸드셰이크.
- 레지스터 읽기, busy: 같은 방식으로 재검토.
- OPL3 레지스터 FIFO(`clk_host = clk`): 비동기 FIFO라 그대로.
- PCM 출력 -> 오디오 믹서: 도메인 확인 필요.
- `ymf278b_top`의 `clk`를 쓰는 다른 로직(레지스터, IRQ/ack 감지, 디버그)도 함께 이동.

## 5. SDC

`MSX1.sdc`의 PCM 멀티사이클은 v2 이름(`stage_a_reg`, `next_pos_r`)을 가리킨다. 지금
엔진에 그 이름이 있는지, TimeQuest가 무시하는지 확인하고 정리한다. 목표는 PCM 내부
멀티사이클 없이 7.76 ns 통과.

## 6. 검증

1. 골든 PCM 하네스와 레지스터 파일 lockstep 벤치(3978fbd)로 85.9 MHz와 비트 일치.
2. 슬롯 예산 최악(페치 4워드)과 CPU 예약 구간이 1프레임 안에 처리되는지.
3. 이 브랜치에서 PCM 경로가 7.76 ns를 통과하는지 재컴파일.

## 순서

1. 스케줄 파라미터화 (85.9 MHz 비트 일치)
2. MLAB 읽기 레지스터와 상태 분할 (85.9 MHz 비트 일치)
3. 128.86 MHz 연구 빌드로 PCM 타이밍 확인
4. ch4 32비트 쌍 읽기 (TDM 컨트롤러와 함께)
5. 클록 도메인 경계와 SDC 정리

1-3은 SDRAM 컨트롤러와 독립적이다.

## 진행 기록

### 1단계 완료 (e324b22)
프레임/예약/헤더 가드를 `CLK_HZ`에서 계산. 골든은 85.909 MHz에서 모델과 일치하고,
128.86 MHz(프레임 2922 확인)에서 8개 시나리오 8,200프레임이 85.909 MHz 출력과 바이트
단위로 같다. 매 클록 lockstep 64회 불일치 0, 변형 4종 모두 검출.

### 2단계 첫 묶음: 슬롯 내부 데이터 경로 분할
`PIPE = (CLK_HZ > 100 MHz)`일 때만 상태를 추가한다(`PIPE_FORCE`로 강제 가능).
ADV0, INTERP2/3, EGPRE, GAIN2, MUL1B/2B, PANB. 슬롯당 +8클록. 85.909 MHz에서는
회로가 그대로다.

검증 방식에 대해 알게 된 것:
- 매 클록 lockstep은 상태를 추가하면 구조상 전부 불일치한다.
- `+samples`(엔진별 메모리, 샘플만 순서대로 비교)는 타이밍이 그대로인 변경에서는 유효하다.
  1단계 엔진으로 64회 0, 변형 4종 모두 샘플 단위에서도 검출.
- 그러나 스트레스 자극은 새 엔진의 내부 시점(디스패치 등)에 쓰기를 넣으므로, 타이밍이
  바뀐 엔진과 기준 엔진에서는 같은 쓰기가 다른 처리 시점에 떨어져 출력이 각자 정당하게
  달라진다. 그래서 타이밍이 바뀌는 변경의 판정 기준이 될 수 없다.
- 판정은 이렇게 나눈다: 충돌 의미(디스패치, MLAB)는 PIPE=0 매 클록 스트레스로 회로
  동일성을 증명하고, 분할의 정확성은 128.86 MHz 골든 비트 일치와 스트레스 없는 샘플
  비교로 본다.

85.909 MHz 프레임에서 PIPE를 강제로 켜면 24음 시나리오에서 슬롯 예산을 넘는다
(프레임 끝 CPU 예약이 슬롯을 버림). 기준 엔진도 85.909 MHz, 24음, 지연 20에서
4프레임이 잘린다. 128.86 MHz는 프레임이 974클록 길어 +8 x 24 = 192클록을 충분히 덮는다.

### 남은 실패 경로 (128.86 MHz 연구 빌드 기준, 이 묶음 이후 재측정 필요)
- `cur_slot` 팬아웃: 디스패치에서 `tl_cur`, MLAB 쓰기 주소, `w_dyn`/`w_hdr`/`w_regs` 적재
  (-1.59 ns). 쓰기/읽기 충돌 의미가 걸려 있어 따로 다룬다.
- `inv_idx` -> `cache_vld` 무효화 순회 (-1.53 ns)
- `accum_r` -> `pcm_right` 출력 포화 (-1.39 ns)
- `w_slot` 인덱스 읽기: `w_gain_t`(tl_cur), `w_word`(캐시 워드) (-1.1 ns)
