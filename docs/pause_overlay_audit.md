## 1. 감사 기준별 결과

### 기준 1 — 공용 신호 수정 전 소비자 전수조사 (HIGH-1 반영): **합격 (독립 재확인)**

감사자 grep 전수조사 결과, 게이트 해제된 두 신호의 소비처는 정확히 다음뿐:

| 신호 | 소비처 (전수) | 성격 |
|---|---|---|
| `ce_10m7_p` | `rtl/msx.sv:518` (vdp18 `clk_en_10m7_i`) | vdp18 비디오 코어 유일 |
| `ce_5m39_n` | `rtl/msx.sv:474` (`ce_pix` mux vdp18 팔) | 픽셀 CE 유일 |

MSX1.sv:460-466 주석이 이 조사 결과를 코드에 박제 — 프로토콜(feedback_vdp_timing_change_protocol
항목 1) 준수. 추가로 감사자가 2차 부수효과를 독립 검증:

- **V9938 정렬 주장 사실**: `rtl/msx.sv:551` vdp는 raw `CLK21M` 구동, 원래부터 pause 미게이트.
  ungate는 vdp18을 기존 V9938 시맨틱에 맞춘 것이 맞다.
- **CPU 동결 중 vdp18 가동의 유일한 신규 상호작용 = CPU 버스 인터페이스**: pause가 I/O 사이클
  중간에 걸려 csr_n/csw_n이 장기간 어서트 유지되는 경우를 `rtl/video/vdp18/vdp18_cpuio.vhd`
  FSM으로 확인 — 부작용 동반 동작(`sched_rdvram_s`/`sched_wrvram_s`/`destr_rd_status_s`/주소증가)은
  전부 **액세스 종료 천이(`transfer_mode_v = TM_NONE`)에서만** 발생하고, 상태 내 반복 동작
  (`wrbuf_cpu_s`, `write_tmp_s`, `write_reg_s`)은 동결된 버스(cd_i 불변) 재기록이라 멱등.
  → 재트리거/이중증가 없음. 안전.
- 잔여 시맨틱 변화 = pause 중 vdp18 vblank INT가 래치되어 unpause 직후 1회 서비스됨 —
  V9938 경로와 동일한 기존 시맨틱이므로 정렬로 판단.
- pause 외 상태(정상 플레이)는 게이트 항등(`ce & 1`)이라 비트 동일 — V3① 무영향 근거 유효.

## 2. 지적사항 (Findings)

- **F-1 [MEDIUM] 문서 정합성 — HIGH-1 반영이 스펙/설계서/TB 헤더에 미반영.**
  ce ungate로 (a) 스펙 배경의 "기존 경로 무침습"·C3 "배선만"이 문언상 깨졌고, (b) 설계 I5/I17의
  "ce 게이트 불변" 문구가 사실과 불일치하며, (c) tb_pause_freeze 헤더(1-9행)는 수정 **이전**
  게이팅(MSX1.sv:460-464 `~msx_pause`)을 현재형으로 서술 — 지금은 F2/F3의 동결 시나리오가
  vdp18 실기에서 발생하지 않는다(TB 자체는 DUT 방어 거동 검증으로 여전히 유효). 권고: 스펙에
  "C3 예외 — A4 HIGH-1로 ce_10m7_p/ce_5m39_n ungate (근거 MSX1.sv:460-466 주석)" 개정 각주
  1줄 + TB 헤더에 '수정 전 상태 기록' 표기. 코드 주석에는 근거가 완비되어 있어 심각도 MEDIUM.
- **F-2 [LOW] C4 ALM 예산은 설계 추정(~79)일 뿐 합성 미검증.** 첫 빌드에서 fitter 리포트로
  확정할 것. 21.5MHz 도메인·레지스터드 입력이라 리스크는 낮음.
- **F-3 [배포 전 조건] 프로토콜 항목 3(전역 타이밍 변경 시 장르 다른 게임 2개+ 실기 검증) 미이행.**
  ce ungate는 pause 중에만 발현되지만 vdp18 전 머신 공통 경로 변경이므로, V3 체크리스트 실행 시
  **vdp18 머신에서 pause 진입/해제 전후 게임 2종 이상**(장르 상이) + V9938 머신 1종 회귀를 묶어
  수행할 것. 배포 RBF는 명명규칙 `MSX1_<YYYYMMDD><letter>_<desc>.rbf` 준수.

## 3. 종합

설계→구현→TB→리뷰→반영의 사슬이 산출물로 재구성 가능하고, 리뷰가 실재 결함(HIGH-1)을 잡아
소비자 전수조사를 동반한 최소 수정으로 반영됐다. 감사자 독립 재검증(TB 재실행 34/34·5/5,
소스 인용 전수 대조, cpuio FSM 안전성 확인)에서 불일치 없음. F-1 문서 개정과 F-3 실기 게이트를
이행하면 배포 가능 상태로 판단한다.
