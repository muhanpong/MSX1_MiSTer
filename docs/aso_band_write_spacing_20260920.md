# ASO 상하 밴드 — 진범은 VDP 레지스터 쓰기 간격 (20260920)

전임 세션이 "게임측 CPU 속도 종속 설계, 재시도 금지"로 닫았던 건을, 실기 기준값을
확보한 뒤 다시 열어 원인을 특정했다. **코어에서 고칠 수 있는 결함이 맞다.**

## 1. 실기 기준값 확보

`Panasonic_FS-A1GT`(512KB)로 **원본 ASO**를 openMSX에서 구동해 기준을 잡았다.
FS-A1ST(256KB)는 ASO가 요구하는 free 매퍼 세그먼트 14개를 못 채워
`ERROR: Not enough memory`로 죽는다(외부 `ram2mb`는 카운트에 안 잡힘).

- 실기 R800: **상단 빈 줄 0 / 하단 빈 줄 0** — 필드가 화면 위까지 차고 패널이 바닥에 붙음
- 타이틀까지 에뮬 시간 약 70초(FDD에서 224KB OVL 로드). 그 전까지 파란 빈 화면은 정상

## 2. 기구 — 축은 하나

프레임(262라인) 구조:

| 라인 | 사건 |
|---|---|
| ~125 | 라인 인터럽트 #1 (중단 분할) |
| ~231 | 라인 인터럽트 #2 → HR 폴링(6CB8, 46 µs) |
| **232** | **패널 리포인트**(6CCC): R#26/27=0, R#0=06, R#8=2A(SPD=1), R#16/팔레트, **R#23=0, R#2=1F** |
| 257~17 | **정상 창** |
| 260.7 | 스톡 R800의 복귀 블록(6D29) 시작 |

**패널 시작은 라인 인터럽트가 띄우므로 래스터 고정**(3.58~20MHz 스윕 전 구간 231~237).
속도 의존은 **플레이필드 복귀 한 점**뿐 → 1차원 문제.

복귀 블록(6D30~6D9D) 내부 착지 시점(R800, 쓰기 간격 8.66 µs 기준):

| +라인 | 레지스터 |
|---|---|
| +0.05 | R#19 = (9403) |
| +0.42 | R#5 = BF/B7 (스프라이트 테이블 더블 버퍼) |
| +0.71 | R#16 + 팔레트 15 |
| **+1.24** | **R#23 = (9404)** |
| +1.52 | R#8 = 28 (SPD=0) |
| **+1.78** | **R#2 = 3F** (플레이필드 복귀) |
| +2.05 / +2.32 | R#26 / R#27 |
| +3.14 | R#0 = 16 (IE1 on) |

## 3. 축 1(클럭)은 원인이 아니다

openMSX Z80 클럭 스윕(패치본, FS-A1WX 세이브스테이트):

| Z80 | 리포인트 | 복귀 착지 | 경과 | DJNZ | 상단빈/하단빈 |
|---|---|---|---|---|---|
| 3.58 | 237.1 | 142.4(다음 프레임) | 167.3라인 | 3023 µs | 24 / 28 (교대) |
| 5.37 | 235.0 | 84.6 | 111.6 | 2015 µs | 상단 쓰레기 |
| 7.16 | 233.0 | 54.7 | 83.7 | 1512 µs | 상단 쓰레기 |
| 10.74 | 232.0 | 25.8 | 55.8 | 1030 µs | 24 / 44 |
| 12 / 14 / 16 / 20 | 232~230.9 | 19.9 / 11.7 / 6.4 / 260.8 | 49.9~29.9 | 920~554 µs | 24 / 45 |
| **21.48** | 230.9 | **258.8** | **27.9** | 515 µs | **24 / 45 (여전히 깨짐)** |
| 실기 R800 7.16 | 231.9 | 260.7 | 28.7 | 380 µs | **0 / 0** |

**21.48MHz Z80은 착지 라인이 실기와 사실상 같은데도 깨진다** → 착지 라인·총 처리량은
결정 변수가 아니다. (보드에서 "10.7과 21.5가 같은 증상"이라던 관측도 openMSX가 재현.)

## 4. 축 2(쓰기 간격)가 진범

브레이크포인트로 **블록 진입/이탈 때만** 클럭을 낮춰, 블록 밖 속도는 그대로 두고
쓰기 간격만 바꿨다.

베이스 10.74MHz 고정:

| 쓰기 간격 | 복귀 착지 | 상단빈/하단빈 | 판정 |
|---|---|---|---|
| 2.00 µs | 25.8 | 24 / 45 | 깨짐 |
| 4.00 µs | 26.5 | 24 / 45 | 깨짐 |
| **6.00 µs** | 27.2 | **0 / 0** | **정상** |
| 7.99 / 8.75 / 10.10 µs | 28.0~28.7 | 0 / 0 | 정상 |

착지 라인은 3줄밖에 안 움직이는데 4→6 µs에서 판정이 뒤집힌다 = **간격이 인과 변수**.

베이스 21.48MHz 고정에서는 8 µs도 부족하고 10.1 µs에서 정상 → **필요 간격은 블록 밖
코드 속도에 비례해 올라간다**. 실기 R800은 8.66 µs(연속 쓰기 24회, 블록 전체 214 µs).

**코어 수정 지침**: 값 하나로 끝나지 않는다. 실기 값 8.66 µs를 넣되 **가장 빠른 터보
단수에서 상·하단 빈 줄 0/0을 확인**할 것. 부족하면 ~10 µs까지.

## 5. 무죄 확정

| 대상 | 근거 |
|---|---|
| 2P 패치 빌드 | 패치본 + FS-A1GT(R800) = 0/0 정상 |
| 머신 | A1WX·A1WSX 둘 다 Z80이면 실패(프레임 교대 포함) |
| 코어 고유 바닥 | openMSX Z80도 10.74~21.48 동일 증상 |

## 6. 판정기 함정 (중요)

처음에 판정을 **상단 12줄의 색상 수**로만 했다가, 보드 10MHz의 "상단 25줄이 검게 빔"을
**정상으로 분류**했다. 색상 다양성은 쓰레기만 잡고 blanking을 못 본다.
**정상 기준은 상·하단 빈 줄 0/0**이다. 도구: `tools/omsxprobe/ bands`.

## 7. 스프라이트 정답표 (별건, 20260920 nextz80 세션에서 원인 특정)

ASO는 스프라이트를 쓴다(SPD 강제 OFF 시 26,652픽셀 변화). 상태별 정답표:

| 세이브스테이트 | 스프라이트 (캡처 행 / x) |
|---|---|
| `aso_tb_06` | 15~30 / 198~215, 38~53 / 45~62, 73~96 / 87~194, 130~158 / 111~143 |
| `aso_tb_05` | **9~24 / 59~77** — 행 9~13은 정상 표시영역보다 위(오버스캔) |
| `aso_tb_08` | 43~58 / 215~233 외 4개 |

- R#8 = 28h(플레이필드) / 2Ah(하단 패널), 프레임당 1회 토글
- **R#5 = BF ↔ B7 프레임마다 교대**(어트리뷰트 더블 버퍼, R#11=00) — 한 프레임만 보고
  기준값 일치로 판정하면 안 된다
- 원인(타 세션): afde2e4의 W_ACTIVE 창이 음수 YP를 -2,-1만 허용 → 게임이 R#9를
  192↔212로 바꿔 표시창 닫힘을 피해 가며 만든 **오버스캔 26줄**에서 스프라이트가 꺼짐

⚠ 차분을 **연속 두 프레임**으로 내면 스크롤분이 섞여 "전 라인에 스프라이트" 같은 거짓
결과가 나온다. 같은 세이브스테이트를 두 번 로드해 **동일 프레임**을 렌더할 것.
