작성 2026-10-24, opl4_scratch b90a9d4 기준. 이 문서는 **제안**이다. RTL은 아직 없다. 사양은 `SPEC.md`, 판정은

## 1. 구조: 한 번에 슬롯 하나, 고정 마이크로시퀀스

현행 v3의 장점(한 슬롯을 처음부터 끝까지 순차 처리, CPU 메모리 연산 BUSY 상한이 구조적)을 유지하고,
면적이 큰 세 가지를 바꾼다.

1. **상태는 M10K 두 개** (현행: MLAB 22개 + 플립플롭 배열 + 스냅샷 레지스터).
   - RAM-R (CPU 레지스터): 40비트 × 48워드. 슬롯당 2워드(필드 0-4, 필드 5-9), 바이트 enable.
     포트 A = 엔진 읽기, 포트 B = CPU 쓰기·헤더 백필·CPU 읽기(readback). 지금의 3중 읽기 포트(MLAB 30개)가 사라진다.
   - RAM-S (엔진 상태): 40비트 × 슬롯당 6워드 = 144워드. pos/stepPtr/tl_cur, env/lfo, 헤더 56비트, (선택) 워드 캐시.
     포트 A = 엔진 읽기/쓰기, 포트 B = 헤더 페치 저장.
   - 슬롯별 비동기 플래그(key_retrig, pos_rst, hf_pending, tl_load, key_on_prev, bf_dirty[5])는 지금처럼 24비트 벡터 플립플롭.
     CPU 쪽 set과 엔진 쪽 clear가 같은 클럭에 겹치는 규칙(set 우선)을 그대로 쓴다(`E:1588-1617, 1646-1658`).
2. **연산 자원 공유**: 18×18 DSP 1개(보간, MUL1, MUL2, 팬 L/R, attack, AM 깊이), 24비트 ALU 1개, 24비트 시프터 1개,
   표(ROM) 한 묶음. "한 상태 = 연산 1개" 규칙으로 128.86 MHz에서 SDC 예외 없이 닫는다.
3. **작업 레지스터는 한 슬롯 분량만** (현행 레지스터 2,458개 중 상당수는 스냅샷·PIPE 분할·슬롯별 배열).

RAM 추론은 map 보고서 RAM summary로만 판정한다(SKILL 규칙 3). generate 안의 ramstyle 배열, 고정 인덱스 디버그 읽기는 쓰지 않는다.

## 2. 슬롯 마이크로시퀀스 (128.86 MHz, 클럭 단위)

L = ch4 읽기 지연(요청 → `mem_rd_valid`), k = 이 슬롯이 읽을 워드 수(1-4, 보통 1-2). M10K 읽기는 1클럭 레지스터드, DSP는 2단.

| 단계 | 클럭 | 자원 | 하는 일 (현행 대응) |
|---|---|---|---|
| LOAD | 3 | RAM-R/S 포트 A | 필드 워드 2개, 상태 워드 3개 읽기 (`SL_IDLE` 디스패치, 스냅샷 불필요) |
| VIB | 1 | ROM | lfo_cnt 삼각 접기 → `vib_q_tab` (`SL_VIB/VIB2`) |
| STEP | 2 | ALU, SHIFT | (fn+1024+vib) << (8+oct) >> 3 (`calc_step`) |
| ADV | 4 | ALU | stepPtr+step, pos+inc(+carry), end 비교, loop 더하기 (`next_pos_calc`) |
| POSB | 2 | ALU | pos+1 랩 |
| ADDR | 3 | ALU | 바이트 주소 A/B: start + pos×{1, 1.5, 2} (12비트는 pos + pos>>1) |
| FETCH0 발행 | 1 | MEM | 첫 워드 요청 |
| (대기 L 동안) EG | 9 | ALU, ROM, DSP | rate 계산, shift/select/inc 표, do_update, attack 곱(DSP), 상태 전이 비교 |
| (대기 L 동안) AM·GAIN·TL | 7 | ALU, DSP, SHIFT | AM 삼각×깊이, env+AM 클립, vmul/vsh → env 이득, TL 보간 한 걸음, TL 이득 |
| FETCH1..k-1 | (k-1)(L+2) | MEM | 나머지 워드 (A의 둘째 워드, B 쌍) |
| DECODE | 2 | — | 바이트 선택, 12비트 니블, 부호 |
| INTERP | 4 | ALU, DSP | (sb-sa) × frac, + sa |
| MUL1, MUL2 | 6 | DSP | × env 이득 >>15, × TL 이득 >>15 |
| PAN | 4 | DSP | × gl, × gr (연달아 발행) >>5 |
| ACC | 2 | ALU | accL, accR |
| WB | 2 | RAM-S 포트 A | pos/stepPtr/tl, env/lfo 쓰기 (캐시 채움은 FETCH 중에) |

슬롯 하나 T = 16 (LOAD~ADDR+발행) + max(L+2, 16) + (k-1)(L+2) + 20 (DECODE~WB).
EG/AM/이득 계산(16클럭)을 첫 워드 대기 안에 숨긴다. 이것이 "슬롯 하나씩"을 유지하면서 메모리 대기를 버는 유일한 장치다.

CPU 메모리 연산(reg 6 읽기/쓰기)은 **슬롯의 워드 요청 사이**에 끼워 넣는다(메모리 포트가 비는 순간마다 우선권).
CPU가 기다리는 최악 = 진행 중 워드 하나 + 자기 요청 하나 ≈ 2(L+2).

## 3. 프레임 예산표 (2,922 clk)

| 구간 | 보통 (k=2, L=16) | 무거움 (k=3, L=24) | 최악 (k=4, L=40) |
|---|---|---|---|
| 슬롯 T | 16+18+18+20 = **72** | 16+26+52+20 = 114 | 16+42+126+20 = 204 |
| 슬롯 24개 | 1,728 | 2,736 | 4,896 |
| CPU 메모리 연산 예약 (L+4) | 20 | 28 | 44 |
| 헤더 페치 1개 (워드 6-7개) | 7×18 = 126 | 7×26 = 182 | 7×42 = 294 |
| 출력(믹스·포화) | 3 | 3 | 3 |
| 합계 | **1,877 (64 %)** | 2,949 (101 %) | 5,237 (179 %) |
| 여유 | 1,045 | -27 | -2,315 |

- "보통"은 남는다. 남는 시간은 추가 헤더 페치(SPEC H4: 프레임당 1개 → 여러 개)에 쓴다.
- "무거움"부터는 넘친다. 현행과 같은 처리: 프레임 끝 예약 구간에서 진행 중 슬롯을 버리고 다음 프레임에 이어간다(`E:1187-1191`, 소리 끊김).
  넘침을 줄이는 수단, 효과 큰 순:
  1. **워드 캐시 유지** (RAM-S에 태그 2개 + 워드 4개, ALM 거의 없음): 저음 보이스는 k=0. 현행이 이것으로 버틴다(`E:354-391`).
  2. **ch4 쌍 읽기 포트** (BL2 두 워드를 한 번에, `docs/sdram_tdm_design.md:91-92`): k가 절반. 엔진 포트(`mem_rd_data16`)를 바꾸는 일이라 드롭인 범위 밖. 별도 단계로.
  3. 첫 워드 대기에 숨기는 연산을 늘림(지금 16클럭).
- **P2 첫 작업은 L 측정**: fullsys(FS-A1GT, tdm128, MoonSound 재생 + R800 CPU 부하)에서 ch4 요청→valid 지연 분포(중앙값, p99, 최대).
  "1~40"(PLAN)은 측정 근거가 문서에 없다. 표의 세 열 중 어느 것이 현실인지 이것으로 정한다.

## 5. 메모리 접근과 CPU 가시 시간

- **쓰기 반영 = BUSY 해제** (PLAN 목표 5, SPEC H2/D2): 엔진이 쓰기를 발행하고, 2클럭 뒤부터 `mem_busy`가 0이 되는 순간을 "반영"으로 본다.
  msx.sv 브리지는 쓰기 동안 `ms_mem_busy`를 1로 둔다(`msx.sv:1885-1902, 1950`) — 포트 추가 없이 된다.
  골든 TB의 메모리 모델은 쓰기에 busy를 올리지 않으므로(`tb_golden_pcm.sv`), "2클럭 뒤 0이면 반영"이 그대로 맞는다(현행 `SV_CPU_WR_SETTLE`의 교착 주의 주석과 같은 이유).
- 그 위에서 CPU WAIT = 쓰기 반영까지(목표 ≈ 107 clk = 0.83 µs, openMSX MEM_WRITE_DELAY 28 마스터 클럭). `MEM_WRITE_DELAY` 1024는 없앤다.
  memwr 게이트(R800 OTIR 1024바이트 + 읽어 비교)와 그 음성 대조(지연 0)는 그대로 둔다.
- reg 6 읽기: ack를 데이터 도착에 묶는다(SPEC H1). `T:271`의 `pcm_reg_rd_done = 1`을 엔진 신호로 바꿈(엔진 포트 `cpu_mem_busy`로 충분한지 P2에서 확인).
- 헤더 페치: 프레임 끝 서비스 + 재생 중 슬롯의 즉시 스톨(SPEC S-STALL)을 유지하되, 남는 시간에 여러 개 처리(H4).

## 6. 리셋

M10K는 리셋이 없으므로 현행처럼 **reset 동안 쓸기**(RAM-R 48워드, RAM-S 144워드 → 144클럭 이상). 하드웨어 reset_ms ≥ 252 clk(`E:1423-1435`)라 충분하지만
전제 클럭 수가 24 → 144로 늘어난다. stress의 must-fail 길이(`reset_len=8`)도 새 전제에 맞춰 바꾼다(예: 100은 실패, 256은 통과).

## 7. 하네스와의 연결, 결정이 필요한 것

- 모듈: `ymf278_pcm_engine3`(새 파일), 포트는 `ymf278_pcm_engine2`와 동일. 벤치(`tb_golden_pcm.sv`, `tb_cpuvis.sv` 경유 top)는 엔진 모듈 이름을 매크로로 받게 바꾸고(기본 engine2), 하네스가 `+define`으로 고른다. 엔진 교체는 qip 교체(PLAN §3).
- 게이트 순서: P2 = cpuvis(D2를 "반영 기준"으로 바꾼 모델 플래그) + memwr + golden 일부, P3 = golden 18개 + 새 엔진용 뮤턴트 생성기, P4 = fullsys, P5 = resource/STA.
- stress 게이트(`run_stress.sh`)는 **현행 엔진과 사이클 단위 lockstep**이라 새 엔진에는 그대로 못 쓴다. 대안: "슬롯 LOAD 순간 직전/직후 쓰기"를 겨냥한 무작위 쓰기 + 프레임 출력 비교(쓰기 반영 시점을 TB가 엔진의 LOAD 신호로 기록해 모델에 알려줌). P2에서 설계.

결정 요청:
1. D3(메모리 접근 모드 무시), D4(reg 3/4가 주소를 즉시 바꿈), D7(reg 6 읽기가 프리페치 값) — openMSX대로 고칠지(권장: D4, D7 수정, D3는 소프트웨어 영향 확인 후).
2. M10K 예산: PCM에 M10K 2-3개를 쓰면 MoonSound 합계가 16-17개가 된다(PLAN 목표 "15개 이하"와 충돌). 장치 여유는 230개.
3. 워드 캐시 유지 여부(유지 권장, L 측정 뒤 확정).
4. ch4 쌍 읽기 포트(엔진 포트 변경)를 이 재제작에 넣을지, 별도 단계로 미룰지(권장: 미룸).
