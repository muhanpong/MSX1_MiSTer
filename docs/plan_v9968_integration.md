# V9968(+Geo3D) 통합 계획 (2026-10-20)

브랜치 `sdram128-study`. 목표는 V9958을 V9968로 바꾸고 V9958 호환을 검증하는 것이다. 그 뒤 이 브랜치가
릴리스 브랜치가 된다(nextz80로 합치지 않음, 사용자 2026-10-20). 시작점은 03a1f21이다
(TIMING PASS +0.235, fullsys PASS, `docs/evidence_20261020/fit_03a1f21.txt`).

원본은 **upstream HRA! `~/data/V9968_Cartridge` origin/main 7820668**(2026-10-19, Geo3D v2.0.0)이다.
포크 `_alexmoncks`의 geo3d RTL은 upstream에 들어갔다(geo3d_z80if.v 포함). VDP RTL은 f327563 이후로
바뀌지 않았다. 아래에서 `파일:줄`은 `fpga/V9968_Cartridge_TangNano20K/src/` 기준이다.

## 0. V9968 쪽 사실 (조사 2026-10-20, 근거는 줄 번호)

| 항목 | 사실 |
|---|---|
| 클록 | VDP 전체가 85.909 MHz 하나로 돈다(VRAM 쪽 클록 enable 없음). "42.95 MHz" 주석은 낡은 것 |
| VRAM 슬롯 | `screen_pos_x[3:0]` 16클록 주기에 슬롯 a(h=1, 화면·스프라이트, 비면 명령), b(h=9, CPU·명령). valid는 1클록 펄스이고 h=2/10에서 high다. **8클록마다 최대 1회** |
| 읽기 지연 | **ready·stall 입력이 없다.** 데이터를 고정 시각에 받는다. 화면 읽기는 valid 뒤 **8~9클록(85.9)** 안에 `rdata_en`이 와야 한다(screen_mode.v:474). 스프라이트는 10~11클록까지 된다. ip_sdram은 정확히 8클록에 준다 |
| 응답 경로 | rdata_en이 오면 h=1/9에 래치해 둔 선택으로 요청자를 고른다(vram_interface.v:280-301). 늦으면 다른 요청자에게 간다. 놓친 요청은 검출하지 않는다 |
| 쓰기 | 응답 없이 보내고 끝이다. 마스크 1 = 쓰지 않음(DQM 극성) |
| 리프레시 | 라인마다 한 번(5472클록 = 63.69 us, half_count 384, 수평 귀선). 그 뒤 슬롯 a,b,a 세 개(24클록)는 CPU·명령을 막는다. 화면·스프라이트는 그 자리에 요청이 없다고 **가정한다** |
| 영상 | 31.40 kHz만 낸다(2736클록/라인, DE 800x480, 픽셀 2클록마다 = 42.95 MHz, 524/626라인). 15 kHz는 없고 인터레이스는 흉내만 낸다. 라인 버퍼는 1024x24 4개 |
| CPU 버스 | valid/ready 핸드셰이크, 읽기 데이터는 나중 펄스로 온다. 포트 98-9Bh는 V9958 호환이고, 9Ch(확장 잠금), 9Dh·9Fh(Geo3D)가 새로 생긴다. **리셋 기본은 V9958 모드**(ID V9958, VRAM 128K, 확장 명령 꺼짐) |
| 미구현 V9958 비트 | R#8 MS/LP/CB/BW, R#9 S1/S0/DC, R#25 WTE/VDS, R#0 DG/IE2, S#2 bit3:2 고정 11 |
| Geo3D | 버스는 85.9 MHz, 엔진은 42.95 MHz(토글 CDC). **VRAM에 직접 접근하지 않는다.** VDP 명령 레지스터(R#36-46)에 `ext_cmd_*`로 쓴다. 메모리 약 310 Kbit |
| 자원 (Gowin) | VDP: LUT 6.5k / ALU 0.75k / REG 4.2k / BSRAM 10 / DSP 11. Geo3D: LUT 5.2k / ALU 1.4k / REG 3.4k / BSRAM 20 / DSP 7 |
| 라이선스 | v9968 파일은 HRA! 3조항(비상업)으로 지금 VDP와 같은 위치다. Geo3D는 MIT(Alex Moncks) |

## 1. 코어 쪽 사실

- 현재 fit(03a1f21): ALM 30,118/41,910(72%), M10K 435/553, DSP 53/112.
  V9958 `VDP:vdp_vdp` 1,140 ALM / M10K 5, VRAM `vram_hi`+`vram_lo` M10K 128(각 64) + ALM 166.
  TMS9918(`vdp18_core`)은 340 ALM이고 `vram_lo`의 16 KB를 쓴다.
- PLL(`rtl/pll/pll_0002.v`)은 50 MHz 기준 분수형이고 출력은 2개(128.863620, 21.477270)다.
  **85.909 MHz(=128.86x2/3)와 42.95 MHz는 없다.** 같은 VCO에서 나눌 수 있다(예: VCO 515.45 MHz를 4, 6, 12, 24로 나눔).
- sdram_tdm V 포트: 프레임(12클록, 128.86 MHz) 경계에서 `v_req`를 보고, 같은 프레임 cycle 11 끝에
  `v_rvalid`를 낸다. V 칩에 리프레시가 걸려 있으면 거절한다(`v_grant=0`, sdram_tdm.sv:624).
- 12클록 at 128.86 = 8클록 at 85.909. 한 PLL에서 나오므로 위상이 고정된 유리수 교차다.

## 2. 핵심 위험과 해법 후보

### R1. 읽기 지연 예산: 여유가 반 클록 남짓
V9968 화면 읽기는 valid(85.9 h=2)에서 rdata_en까지 8~9클록 = 128.86 기준 12~13.5클록이 허용된다.
V 슬롯 자체가 요청을 본 경계부터 v_rvalid까지 12클록이다. **교차(85.9 → 128.86 → 85.9)에 쓸 여유는
1.5클록(128.86)뿐이다.** 그래서
- TDM 프레임 경계를 V9968의 h 위상에 **고정 정렬**해야 한다. 리셋 때 한 번 맞추고, 같은 PLL이라 계속 유지된다.
  valid가 경계 직전에 서도록 하고, 응답은 동기 레지스터 한 단으로 85.9 쪽에 넘긴다.
- 정렬은 위상 비교로 감시한다: 시뮬 assert, 실기에서는 OSD 디버그 카운터("늦은 rdata_en" 수).
- 안 되면 V9968 쪽에서 화면 표본을 한 클록 늦추는 수정(sub_phase 12 → 13)이 대안이다. 원본 수정이므로 최후 수단이다.

### R2. 리프레시: V9968의 라인당 1회로는 MiSTer 칩에 모자란다
MiSTer 칩은 64 ms에 8192행이 필요하다(7.8 us마다 1회). V9968은 63.69 us마다 1회라 약 8배 부족하다.
제안: V9968의 리프레시 차단 창(`ff_vram_refresh`, 지금 슬롯 3개)을 **N슬롯으로 늘리는 매개변수**를 넣는다(원본 수정 최소).
그 창 안에서 컨트롤러가 V 칩을 **라인당 9회 연속 리프레시**한다(64 ms에 약 1005라인 x 9 = 약 9040회 ≥ 8192; 8192회를 채우는 데 911라인 = 58.0 ms).
- 창 위치: half_count 384에서 화면 시작(640) 사이 256클록(32슬롯)에는 화면 읽기가 없다(조사 3절).
  스프라이트 수집이 그 전에 끝나는지는 시뮬에서 assert로 확인한다.
- 연속 리프레시가 데이터시트상 합법인지(AS4C32M16SB: 64 ms에 8K, 분산·연속 언급) 확인한다. sdram_chk의
  "7.8 us 간격" 검사를 "64 ms 창 + 최대 공백" 규칙으로 바꾸고, 음성 대조군을 단다.
- 128 MB 보드: V 칩(칩 1)에는 일반 영역 16-28 MB도 있다. 그 창 동안 칩 1의 G 접근이 막힌다(CPU 마감에 영향 → R3).
- 32/64 MB: 칩이 하나라 칩 전체 리프레시가 이 창에 묶인다.

### R3. 32/64 MB에서 CPU 마감 (이미 알려진 미해결)
v_en=1, 행 비트 01, g3/15/27 위상에서 E0+29 LATE가 난다(432de57, run.sh INFO 줄).
여기에 R2의 리프레시 창이 더해진다. 해법 후보:
(a) ch2_req_s 한 클록을 G1 결정 위상에서 되찾기 — 요청 표본 위치를 프레임에 대해 조정.
(b) 행 비트 01의 CPU를 받는 예약 규칙(rsv)을 한 클록 앞당기기.
(c) 32/64 MB 맵에서 CPU 영역을 행 비트 00으로 옮기기(맵 변경).
판정은 단위 벤치의 v_en=1 고정 위상 실행을 통과 조건으로 바꾸는 것으로 한다.

### R4. 자원
빠지는 것: V9958 1,140 ALM, M10K 133(VRAM 128 + 5). TMS9918용 16 KB(M10K 16)는 남긴다 → 실제로 약 117개가 빠진다.
들어오는 것(Gowin 수치를 대략 환산, 미측정): VDP 약 4-5k ALM, Geo3D 약 4k ALM, M10K 약 50, DSP 약 20.
**ALM이 30.1k에서 약 37-38k(88-91%)로 오를 것으로 추정한다. 이게 가장 큰 위험이다.** M10K는 435에서 약 370으로 줄어든다.
→ 1단계에서 V9968과 Geo3D를 따로 합성해 Cyclone V ALM을 먼저 잰다(fit 없이 map만).

### R5. 영상: 31 kHz만 나온다
HDMI(스케일러)는 문제없다: CLK_VIDEO 85.909, ce_pix 42.95 MHz, 800x480.
아날로그 15 kHz 사용자는 MSX2 화면을 잃는다. **사용자 결정 사항이다**(V9958을 OSD 선택으로 남기면 R4가 더 빠듯해진다).

### R6. CPU 쪽 접근 지연
V9968 읽기 데이터는 핸드셰이크 뒤 펄스로 온다. 표준 속도 Z80의 I/O 읽기 창(약 2.5 T-state) 안에 오는지,
포트 98h 읽기(VRAM 선읽기)를 포함해 시뮬로 잰다. 터보·R800 VDP 페이서(`vdp_hold`, OSD r800_vdpw)는 새 지연에 맞춰 다시 본다.
포트 9C-9Fh와 다른 장치의 디코드가 겹치는지도 확인한다.

## 3. 단계 (각 단계의 판정 기준)

| 단계 | 내용 | 판정 |
|---|---|---|
| S1 | upstream 7820668에서 v9968/geo3d를 `rtl/video/v9968/`로 가져오기(원본 그대로, 해시 기록, HRA! 표시). PLL에 85.909 / 42.95 출력 추가. V9968+Geo3D를 MSX1과 따로 map해서 ALM·M10K 측정 | ALM 추정이 맞는지. 넘치면 Geo3D를 합성 옵션으로 |
| S2 | VRAM 교차 브리지 + V 슬롯 위상 정렬 | 단위 벤치: V9968 vram_interface(실물)+브리지+sdram_tdm+sdram_chk. rdata_en이 언제나 +8(85.9), 놓친 valid 0. 음성 대조: 정렬을 한 클록 틀리면 실패해야 함 |
| S3 | 리프레시 창(V9968 매개변수) + 컨트롤러 연속 리프레시 | sdram_chk 64 ms 규칙 통과, 창 안에서 화면·스프라이트 요청 0(assert), 음성 대조 |
| S4 | 32/64 MB CPU 마감(R3) | run.sh v_en=1 고정 위상이 통과 조건으로 PASS |
| S5 | msx.sv 통합: CPU 버스 어댑터, 인터럽트, 포트 디코드, 영상(CLK_VIDEO), OSD | fullsys: MSX2+ 팩 부팅, BIOS 로고. VRAM은 openMSX와 대조 |
| S6 | V9958 호환 검증 | VDP 재생 하네스(`sim/run_vdp_replay.sh`)를 V9968 RTL로: openMSX 녹화 VRAM 일치. 화면은 openMSX 스크린샷과 sim 프레임 비교. HRA! 호환 목록(30개, NG 5)의 제목 |
| S7 | 빌드·타이밍(85.909 / 42.95 / 128.86 세 도메인 STA, relations), 실기 | TIMING PASS 후 실기 1회(결론을 가를 때만) |
| S8 | Geo3D 시연 | Geo3D 데모 ROM 실기 |

memory_upload의 VRAM 영역 한도도 S5에서 같이 정한다(sdram_tdm_design.md 13절: v_en=1이면 뱅크 3 G 접근이
영원히 거절되어 업로드가 멈춤. 32 MB에서 카트 둘 + MoonSound면 24.42 MB > 24 MB).

## 4. 사용자 결정이 필요한 것

1. 15 kHz 아날로그: V9968만 쓸지(31 kHz), V9958을 OSD 선택으로 남길지.
2. Geo3D: 기본 포함인지 합성 옵션인지(ALM 결과를 보고).
3. V9968 원본 수정 허용 범위: 리프레시 창 매개변수(R2)는 필요하다. 화면 표본 지연(R1 대안)은 최후 수단.
4. 32 MB 보드에서 큰 구성(카트 둘 + MoonSound)이 VRAM 뱅크와 겹칠 때의 정책.
