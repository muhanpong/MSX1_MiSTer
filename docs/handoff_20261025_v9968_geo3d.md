## 2. 열린 문제 (우선순위 순)

1. **R800 VDP 대기 < 3 µs에서 SUPER CAT·PRISM FLIGHT 화면 깨짐** (원인 미확인, 다이얼은 그대로 두기로 결정).
   - 시뮬레이션으로 재현 안 됨: 게임 프레임 루프, LRMM 중 98h 쓰기, 접근 손실 프로브 모두 0.
   - 기각된 가설: CE 확인 없이 명령 시작(두 데모 모두 `wait_command`, openMSX 기록 2,115회 전부 가드).
   - STA(1025a s18): CPU↔V9968 버스 2.4–5 ns 여유, `v_rdata`→V9968 +0.105 ns.
   - 두 데모 공통 패턴: LRMM 실행 직후 98h로 스프라이트 속성 OTIR(80/48바이트 + 종료 8바이트), 스프라이트 모드3.
   - **다음 단계: 보드에서 `LRMMWR.ROM` 실행** (`/data/_claude/tmp/msx1-handoff/lrmmwr/`, md5 60001a0c…, 사용자에게 전달됨).
     다이얼 None과 8.66 µs로 각각 1회. 6개 시험 × 256회, 줄마다 [빠른 읽기 오류, 느린 읽기 오류, 겹침 횟수].
     openMSX에서는 모두 0, 겹침 256/0/256/256/256/256. 1번만 None에서 빨갛고 4번(3 µs 간격)이 초록이면 증상 재현.
2. **FH 클리어 규칙의 남은 차이** (`vdp_cpu_interface.v:918-924`): R#0/R#19에 무엇을 쓰든 FH를 지우고, 같은 클럭의 라인 일치를 놓침.
   openMSX는 IE1을 끄는 R#0 쓰기만. 수정 시 `run_irq.sh`에 "핸들러에서 R#19 재기록" 경우와 뮤턴트 추가.
3. **ASO 패치 정리 제안(미착수)**: 7fcf4fe·ff50884를 `run_irq.sh`의 회귀 시험으로 고정, V9958 빌드 다이얼의 9.3 µs 이상 항목 정리,
   `docs/handoff_20261023_aso_paused.md`에 해결 포인터 추가.
4. **Shaolin's Road(V9968판, 다른 세션 shaolin-v9968)**: 오버스캔 + 화면 끔 중 검은 화면은 게임 쪽 우회로 사라짐, 원인 미확정.
