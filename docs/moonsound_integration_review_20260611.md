## 총평 (Executive Summary)

| 질문 | 결론 |
|---|---|
| **① 표준 MSX 버스 규합성** | **대체로 규합** — 포트 디코드(0x7E/7F, 0xC4-C7), M1 제외, WAIT/INT 의미론은 표준적. 단, **장치가 버스 동기(3.58MHz)가 아닌 clk_sdram(85.9MHz) 도메인에서 동작하고 토글-CDC로 연결**되는 점이 실물과 다른 근본적 구조 편차이며, BUSY는 실칩 피드백이 아닌 **고정 지연 카운터 에뮬레이션**이다. |
| **② 코어 침습도 / 오버엔지니어링** | MoonSound 귀속 코어 변경은 **약 +894 / −72 라인, 8개 파일** (장치 디렉터리 제외). 변경의 대부분은 기능상 필수(SDRAM ch4, I/O 디코드, 오디오 믹스, INT/WAIT)이고, 약 1/3은 디버그 스캐폴딩(165라인 오버레이 + 13개 dbg 포트 + freeze 검출기)이다. **`moonsound_en=0`일 때 비-MoonSound 동작에 대한 기능적 위험은 사실상 없음.** 활성 시의 잔여 위험 2건(SDRAM ch4 우선순위 홀드, INT wired-AND)은 한정적·완화됨. 장치 내부는 오버엔지니어링이라기보다 **86MHz 타이밍 마감을 위한 필연적 파이프라인 분할**이 대부분이나, 디버그 인프라의 비중이 큰 편. |
| **③ 독립성 / 외장(슬롯 규격) 장치화 가능성** | **가능하나 상당한 재작업 필요.** I/O·오디오·IRQ 인터페이스는 이미 깨끗한 버스형 추상화이지만, (1) CDC와 WAIT 로직이 호스트(msx.sv)에 있고, (2) PCM 메모리가 코어의 SDRAM ch4에 결합되어 있으며, (3) 샘플 타이밍이 85.9MHz를 전제한다. 자체 평가 **독립성 ≈ 55/100**. 외장화 시 신규/수정 코드 ~300-900라인 규모. |

## 1. 표준 MSX 버스 규합성 (조사 ①)

실물 MoonSound는 카트리지 슬롯의 I/O 매핑 장치다: 포트 0x7E/7F(WAVE), 0xC4-C7(FM),
/IORQ·/RD·/WR·/WAIT(칩 BUSY 경유)·/INT(OPL4 타이머) 사용, 보드 자체 ROM/RAM 탑재.

### 항목별 판정

| 항목 | 판정 | 근거 |
|---|---|---|
| I/O 포트 디코드 | **규합** | `msx.sv:231-234` — 0x7E/7F, 0xC4-C7을 8비트 전체 주소로 디코드, 미러 없음. `m1_n` 게이팅으로 **INTA(인터럽트 응답) 사이클 제외 — 올바름**. `moonsound_en`으로 전체 게이트. |
| 읽기 데이터 버스 | **편차 / 위험(중)** | 읽기 데이터는 콤비네이셔널이 아니라 **CDC 왕복 후 래치**(`ms_io_dout_lat`, `msx.sv:655-657`)로 공급. WAIT가 ack까지 CPU를 잡아주므로 정상 경로에서는 신선한 데이터가 보장되지만, **600-cycle 타임아웃으로 풀린 경우 직전 액세스의 stale 데이터를 읽는다.** 실칩은 /RD 동안 칩이 직접 버스를 구동. |
| WAIT_n 처리 | **규합** | `msx.sv:179-203` — 고전 MSX WAIT 회로(74'74 등가)를 에뮬레이트: 비동기 어서트 + 동기 해제, M1 통과. MoonSound I/O 중 WAIT 어서트는 실물 카트리지의 /WAIT 구동과 의미상 동일. 타임아웃 600 clk21m ≈ **28µs**는 실물에 없는 안전장치(교착 방지)로, 표준 일탈이지만 방어적. |
| INT 라인 | **규합** | `msx.sv:162` — `vdp_int_n & ms_irq_n_sync` = open-collector wired-AND의 올바른 모델. 2-FF CDC(`:734-738`)로 메타스테이블 방지. MoonSound는 IM1 전제로 벡터를 공급하지 않음 — 실물과 동일. |
| 클럭 도메인 | **편차(구조적)** | 실물은 단일 버스 클럭 동기 장치. 본 구현은 **clk21m(CPU) ↔ clk_sdram(85.9MHz) 토글-CDC** (`msx.sv:591-662`). WAIT 핸드셰이크로 직렬화되어 안전하지만, "쓰기가 CDC를 추월하면 유실"(`msx.sv:604-608` 주석에 명시)이라는 실물에 없는 고장 모드가 존재 — vgmplay freeze 분석의 근본 배경. |
| 리셋 | **규합** | `msx.sv:787` — CPU 리셋과 동기, active-low. |
| BUSY/LD 상태 의미론 | **편차(소)** | `ymf278b_regs.sv:46-60,106` — BUSY는 실칩 내부 상태가 아닌 **고정 지연 카운터**(FM 56, WAVE 88, MEM_WRITE 1024 cycle 등) + 엔진 in-flight 플래그. BUSY 폴링 드라이버에는 충분하나 실칩 타이밍과 1:1은 아니며, 특히 `MEM_WRITE_DELAY=1024`(≈12µs/byte)는 업로드 스로틀용 **튜닝 값**이다. |
| NEW2 디바이스 ID | **규합** | `ymf278b_regs.sv:77-83,244-249` — NEW2 상승 후 첫 상태 읽기에 0x02 원샷, 데이터시트 일치. |

### 소결

**I/O 의미론 차원에서는 표준 MSX 장치로서 손색이 없다.** 비표준 요소는 모두 "장치를 버스 클럭이
아닌 고속 도메인에서 돌리고 CDC로 잇는다"는 한 가지 구조적 선택에서 파생된다(읽기 래치 경유,
WAIT 타임아웃, 쓰기 유실 가능성, BUSY 에뮬레이션). 이 선택은 FPGA 통합으로서는 실용적이지만,
실물 카트리지와의 본질적 차이이며 현재 진행 중인 freeze 계열 버그의 토양이기도 하다.

### 2.2 비-MoonSound 동작에 대한 영향 평가

| 코어 변경 | `moonsound_en=0`일 때 | `moonsound_en=1`일 때 잔여 위험 |
|---|---|---|
| WAIT 회로 (`msx.sv:179-203`) | `ms_io_pending`은 cs가 게이트되므로 **불활성** | MoonSound I/O에서만 WAIT, 최악 28µs 타임아웃으로 바운드 |
| SDRAM ch4 + CH4_HOLD=24 (`sdram.sv:119-130,318-332`) | ch4 요청 없음 → **영향 0** | PCM 버스트 동안 ch1-3가 최대 24 cycle(280ns) 대기. CPU(ch2) 체감 최악 ~1µs — VDP/CPU 타이밍 여유 내. `tb_trace_wave.sv`로 검증된 튜닝 |
| INT wired-AND (`msx.sv:162`) | `ms_irq_n` 항상 1 → **영향 0** | **OPL IRQ가 stuck-low가 되면 시스템 전체 인터럽트 폭주** — 실측된 위험이며, `timers.sv:124-150`의 4.6ms IRQ 워치독으로 완화됨 |
| 오디오 믹서 (`msx.sv:136-139`) | ms 출력 0으로 게이트 | 포화 가산 — 기존 PSG/SCC/OPLL 경로 변경 없음 |
| memory_upload 제로필/베이스 이동 | 부팅 시 1회, 수 ms | 영향 없음 |
| 디버그 오버레이/검출기 | status[48] OSD로 게이트 | 관찰 전용, 기능 피드백 없음 |

**결론: 침습은 "한정적·게이트됨"** — 모든 변경이 `moonsound_en` 또는 ch4 요청 존재에 조건화되어
있고, 코어의 기존 데이터 경로를 수정한 것이 아니라 **추가**한 것이다. 구조적으로 코어에 박힌
부분은 ① SDRAM 중재기의 ch4 채널과 ② CPU WAIT 회로 연동, ③ INT AND 게이트 세 곳이다.

### 2.3 오버엔지니어링 평가

- **장치 내부 파이프라인(D1a/D1b/D2a/D2b/D2c/D3a/D3, Stage A-D)**: 과설계가 아니라
  85.9MHz(11.6ns) 타이밍 마감 실패(-34ns, -10ns, -5ns 등 코드 주석에 기록)를 해결한
  **필연적 리타이밍**. 다만 그 결과 엔진이 1,981라인으로 비대해졌고, freeze 분석에서 드러났듯
  **중재/소유권 설계가 파이프라인 복잡도를 따라가지 못한 상태**다.
- **슬롯별 디코드 캐시, last_interp 홀드(우아한 성능 저하)**: SDRAM 경합 완화용 — 각각 수백
  비트 수준으로 비용 대비 타당. 단, 캐시·홀드·스톨가드(MAX_STALL=0)·EG_OFF skip 등
  **대역폭 완화 장치가 4중으로 누적**되어 있어, 근본 원인(중재 프로토콜)을 고치면 일부는
  제거 가능한 후보다.
- **디버그 인프라**: 오버레이 170라인 + 모듈 경계를 관통하는 13개 dbg 포트 + 5종 freeze
  검출기 + IRQ 워치독. 진행 중인 freeze 디버깅의 산물로 정당하나, **버그 해결 후 회수(revert)
  대상 목록을 명시적으로 관리할 필요**가 있다 (`ymf278b_top.sv:296-317`의 "REVERT this after
  diagnosis" 주석 등).
- **워크어라운드 누적**: WAIT 핸드셰이크(+타임아웃 600), deferred-ack(MEM_WRITE_DELAY=1024),
  CH4_HOLD=24, IRQ 워치독(4.6ms) — 모두 **증상 완화 계층**이며, 근본 원인이 수정되면
  단순화 여지가 있다.

## 3. 장치 독립성 / 외장(슬롯 규격) 장치화 가능성 (조사 ③)

### 3.1 현재 결합도 — 신호 인벤토리 (msx.sv ↔ `ymf278b_top`, 42개 포트)

| 그룹 | 신호 수 | 외장화 관점 평가 |
|---|---|---|
| 클럭/리셋 (clk=85.9M, clk_opl3=14.3M, rst_n) | 3 | **비표준** — 실물 카트리지는 3.58MHz 버스 클럭 기준 |
| CPU I/O 버스 (port/din/wr/rd → dout/ack) | 12 | **깨끗한 버스형 인터페이스** — 단 CDC·WAIT 로직이 호스트(msx.sv:591-662)에 있음 |
| PCM 메모리 (addr/rd/wr/valid/busy/data16) | 8 | **최대 결합점** — SDRAM ch4 브리지(msx.sv:664-725)+`pcm_rom_base`+16비트 워드 최적화가 코어 SDRAM 컨트롤러에 의존 |
| 오디오 (L/R/valid) | 3 | 표준, 그대로 사용 가능 |
| IRQ (irq_n) | 1 | 표준 — 단 clk_opl3 도메인이라 CDC를 호스트가 수행 중 |
| OSD/뮤트 (pcm_mute, fm_mute, pcm_vol) | 4 | 제거/점퍼 대체 가능 |
| 디버그 (dbg_*) | 13 | 미사용 시 합성에서 제거됨 |

**독립성 점수: 약 55/100.** I/O·오디오·IRQ는 이미 캡슐화가 좋다. 발목을 잡는 것은
(1) 메모리(4MB 웨이브 공간이 코어 SDRAM의 `pcm_rom_base` 오프셋에 상주, `memory_upload`가 로드),
(2) 클럭 전제(프레임 스케줄러 1948 cycle/frame이 85.9MHz 기준),
(3) 호스트 쪽에 있는 CDC/WAIT 프런트엔드다.

### 3.2 외장(카트리지 규격) 장치로의 재포장

실물 MoonSound처럼 "슬롯 커넥터 신호만 받는 자족 장치"로 만들려면:

**필요 인터페이스(슬롯 신호)**: A[7:0], D[7:0], /IORQ, /M1, /RD, /WR, /WAIT(출력), /INT(출력),
/RESET, 3.58MHz CLK — 그리고 보드 자체 메모리(yrw801 2MB ROM + 커스텀 웨이브 RAM 최대 2MB).

| 작업 | 내용 | 규모 |
|---|---|---|
| 버스 동기 프런트엔드 | 호스트의 토글-CDC(`msx.sv:591-662`)를 장치 내부의 버스-동기 래치 + /WAIT 드라이버로 이관. `io_ack`→/WAIT는 사실상 1게이트 | 중 (~150라인) |
| IRQ CDC 내장 | clk_opl3→버스클럭 2-FF 동기를 장치 내부로 이동 | 소 |
| 메모리 내장화 | ch4 브리지 FSM을 장치 안으로 가져와 자체 메모리 컨트롤러(BRAM ROM은 용량 부족 — 2MB ROM+2MB RAM이므로 사실상 **전용 SDRAM/DDR 필요**)에 연결. `pcm_rom_base` 제거(베이스 0 고정). 16비트 워드 최적화는 메모리 종류에 따라 유지/포기 | 중 (~200-300라인) |
| 클럭 전략 | **옵션 A**: 내부 PLL로 85.9MHz/14.3MHz 생성(현 엔진 무수정 재사용 — 현실적 권장) / **옵션 B**: 프레임 스케줄러를 버스클럭 기준으로 재설계(엔진 ~300라인 재작업, 침습 큼) | A: 소 / B: 대 |
| OSD/디버그 정리 | 뮤트·볼륨을 점퍼/레지스터로, dbg 포트 제거 | 사소 |

**판정: 가능 (중간 결합도).** MiSTer 내부 기준으로는 "ch4 브리지 + CDC + WAIT 프런트엔드를
장치 래퍼로 흡수"하는 것만으로도 msx.sv와의 접점을 버스 신호 + 전용 메모리 포트 수준으로
줄일 수 있다(신규/수정 ~300-500라인). 진짜 하드웨어 카트리지 규격까지 가려면 전용 메모리와
클럭 전략(옵션 A 권장)이 추가되어 ~600-900라인 규모로 추정된다. 어느 경우든 OPL3 코어(gtaylormb)와
PCM 엔진 본체는 그대로 재사용 가능하다.

## 4. 권고 사항

1. **(버그 수정 우선)** freeze 정적 분석 보고서의 중재 프로토콜 수정(소유자 태깅, `!mem_busy`
   가드)을 먼저 적용 — 이는 §2.3의 워크어라운드 4종을 단순화할 전제 조건이기도 하다.
2. **(침습 축소)** msx.sv의 MoonSound 블록(CDC, ch4 브리지, WAIT 연동, freeze 검출기 ~250라인)을
   `moonsound_adapter.sv` 같은 단일 래퍼 모듈로 추출 — 코어 수정 표면을 "인스턴스 1개 + SDRAM
   ch4 포트 + INT AND + WAIT 1신호"로 줄일 수 있고, §3의 외장화 1단계와 동일한 작업이다.
3. **(디버그 회수 계획)** dbg 포트/오버레이/진단 모드("REVERT after diagnosis" 주석 포함)를
   목록화하고, freeze 해결 후 일괄 제거 또는 `ifdef` 게이트화.
4. **(문서화)** BUSY 지연 상수(56/88/1024/10000)와 CH4_HOLD=24 등 튜닝 값의 결정 근거가 코드
   주석에 흩어져 있으므로, 본 문서 계열에 타이밍 예산표로 정리해 두면 회귀 방지에 유효.

## 부록: 조사 에이전트 결과에 대한 교정 사항

종합 과정에서 다음 항목을 검증·교정했다:

- (에이전트 ①) WAIT 타임아웃을 "600 cycle @3.58MHz ≈ 168µs"로 기술했으나, 카운터는
  **clk21m(21.477MHz) 도메인**이므로 **≈28µs**가 맞다 (`msx.sv:612,631`).
- (에이전트 ①) "INTA 중 디코드가 구분되지 않는다"는 우려는 부정확 — `ms_wave_cs/ms_fm_cs`에
  `m1_n`이 포함되어 INTA(M1·IORQ 동시 low)는 **이미 제외**된다 (`msx.sv:231-234`).
- (에이전트 ②) footprint 집계에 IKASCC(+2,000라인 이상), ASCII16X, nvram_backup 플래시 DMA,
  SCC 버스 정리 등 **MoonSound와 무관한 동일 브랜치 작업이 혼입**되어 있어, 본 보고서 §2.1에서
  git numstat 기준으로 MoonSound 귀속분만 분리했다.
- (에이전트 ②) "PCM 엔진은 오버엔지니어링이 아님"이라는 평가는 타이밍 관점에서 타당하나,
  freeze 정적 분석에서 확인된 **중재 설계 결함**(완화 장치 4중 누적)을 고려해 §2.3에서
  "근본 수정 후 단순화 여지"로 보정했다.
