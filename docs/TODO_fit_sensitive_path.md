# 배치에 따라 뒤집히는 마진 없는 경로 — 미해결, 우선순위 높음

## 무엇이 확정됐나 (2026-08-30, 실기)

논리적으로 **무해한** 한 줄이 실기 크래시를 만들었다 껐다 한다.

    30a 트리(9baa294) → 30b 트리(0b49f49) 의 합성 대상 변경은 정확히 한 줄:
        rtl/peripheral/slots/memory_upload.sv 의 load 초기화 블록에
        msx_device <= '0;

**그 줄이 논리적으로 무해하다는 증거 3가지:**

1. **영향 범위 전수조사.** `msx_device` 소비처는 `msx_slots.sv` 의 chip-select **4개뿐**이다
   — `DEV_KANJI`(0xD8-0xDB), `DEV_OPL3`(0x7C/0x7D), `DEV_RESET_STATUS`(0xF4),
   `DEV_MATSUSHITA`(0x40/0x41). VDP·인터럽트·SDRAM·타이밍에는 닿지 않는다.
   (부수 발견: **`DEV_MOONSOUND` 는 소비처가 0건인 죽은 비트**다.)
2. **Daewoo CPC-300 은 `<device>` 선언이 0개**다. 전원을 껐다 켜고 첫 팩으로 로드하면
   `msx_device` 는 **30a·30b 양쪽 다 0** — 비트 단위로 동일하다.
3. **벤치**(`sim/run_device_reload.sh`): 그 줄을 모델링해도 기능 차이가 없다
   (P1/P2 통과, P3만 달라짐 = 누수 유무).

**그런데 실기는 갈린다:**

    껐다 킴 → 30b → CPC-300 → 게임 → 크래시 + 머신 재시작
    (전원 안 끄고) → 30a → 같은 머신 → 같은 게임 → 정상 플레이

DDR3 내용·마운트된 팩과 ROM·OSD 설정이 전부 그대로고 **비트스트림만 바뀌었다.**
⇒ 차이는 RTL 의 의미가 아니라 **구현(배치·라우팅)** 이다.

## 유력한 후보: 3.58 에서 VDP 쓰기 유실

증상은 Sony HB-F1XV 에서 **좌하단 큰 VRAM 잡음 사각형 + 플레이어 스프라이트 없음 +
연속음 + 리셋 루프**. Daewoo CPC-300/400S 는 잡음 없이 멈춤+리셋 루프.
**같은 머신에서 OSD CPU 를 5.37 로 올리면 통과한다.**

`rtl/msx.sv` 의 VDP 페이서는 **`cpu_turbo` 로 게이트**된다:

    wire vdp_hold  = cpu_turbo & vdp_bus & ~vdp_grant;
    wire vdp_pace_n = ~(cpu_turbo & vdp_bus & (...));

즉 **3.58 에서는 VDP 접근 간격 강제가 전혀 없다.** 그리고 같은 파일의 주석:

> V9938 is driven by `.REQ(...)` with **`.ACK()` UNCONNECTED**, so a request that
> arrives before the previous VRAM slot completed is **simply lost** -> corrupted
> tiles/sprites, no hang.

3.58 이 안전하다고 본 근거는 "가장 촘촘한 Z80 VDP 접근 쌍이 72 clk21m 간격, VDP 최악
슬롯 주기는 28" 이었다. **그 계산에는 커맨드 엔진이 VRAM 슬롯을 점유하는 경우가 빠져 있다.**
문제의 롬은 커맨드(HMMM 등) 진행 중에 다시 VRAM 에 접근한다 — 그러면 CPU 슬롯이 훨씬
드물어지고 쓰기가 조용히 유실된다. 유실이므로 **행이 아니라 화면 깨짐**이고, 마진 문제라
**배치가 바뀌면 나타났다 사라진다.**

|  | 3.58 | 5.37 |
|---|---|---|
| VDP 페이서 | **꺼짐** | 켜짐(32 clk21m 강제) |
| 커맨드 엔진 중 CPU 쓰기 | 유실 가능 | 보호됨 |
| 실기 결과 | 깨짐 | 통과 |

openMSX 가 같은 머신·같은 롬에서 멀쩡한 것도 이 그림과 맞는다 — openMSX 는 ACK 를
제대로 모델링한다.

   (30a/30b 만으로도 사실상 확증됐지만, 재현 통제를 하나 더 얻는다.)

   ★단, **"3.58 은 스톡과 비트동일"은 이 코어의 설계 불변식**이다(`cpu_turbo=0` 이
   가드·페이서를 전부 단락). 이걸 깨면 회귀 범위가 전 게임으로 넓어진다.
   ACK 를 제대로 연결하는 쪽이 불변식을 지키면서 고치는 길로 보인다.
