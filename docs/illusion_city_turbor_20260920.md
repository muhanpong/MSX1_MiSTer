# Illusion City (turbo R 전용) — 코어 구동 조사 기록 (20260920)

MiSTer에서 부팅이 안 되던 건. **디스크·덤프는 정상**이고, 막힌 지점을 하나씩 걷어내는
중이다. 이 문서는 확정된 사실과 실기 기준 타임라인을 남긴다.

## 1. 디스크 구조

`Illusion City (1991)(Micro Cabin)(ja)(Disk 01 of 13)(Game Disk 1).dsk` (737,280 B)

- 720KB FAT12, 볼륨 `IPROJ01`, BPB 정상(bps=512 spc=2 nfat=2 rootent=112 spf=3)
- 부트섹터: 관례상 `EB FE 90`로 시작하고 **실코드는 +0x1E부터**(`JR +10h` → 0x30에서
  F36B/F37D 디스크 ROM 훅 호출 → `JP 0100`). 즉 **자체 부트로더**로 뜬다
- 보이는 파일 4개뿐: `FRAY.DOS`(3,234), `SAVEDATA.BIN`(8,192), `ARMI.COM`(2,749 — RCP
  MIDI 플레이어, "not found MIDI I/F" 문자열), `ARMI.DOC`(4,633)
- **나머지 용량은 FAT에 F7(bad) 표시로 잠근 raw 섹터 영역**이고 로더가 직접 읽는다.
  Disk 02는 파일 0개 = 순수 데이터. **파일 복사로는 이식 불가, 이미지째 써야 한다**
- 변종: `[a]`는 7,131바이트(섹터 0 포함 12섹터, 부트코드가 1바이트 밀림),
  `[b]`는 **딱 1바이트**(off 0x512C, 섹터 40: `7D`→`97`)

## 2. 실기 기준 — openMSX에서는 정상 부팅

- **FS-A1GT**: FM음원/MIDI음원 선택 메뉴 → 시작 메뉴까지 도달
- **FS-A1ST**(MIDI 없음): 선택 메뉴 없이 곧장 시작 메뉴 = MIDI 부재는 치명적이지 않음
- MSX2+(FS-A1WX): 검은 화면에서 PC=E774 고착 = turbo R 전용이 맞음

## 3. 관문 ① 프린터 상태 포트 90h — 확정·수정됨

보드 정지 PC `08E4`/`08E7`은 게임 코드가 아니라 **MSX BIOS의 LPTSTT**였다.
(turbo R은 BIOS를 DRAM에서 실행하므로 페이지 0 RAM으로 보인다. `illu_st`의 매퍼
세그먼트 12 오프셋 08E4가 BIOS ROM 바이트와 일치.)

```
BIOS 00A8 (LPTSTT) → C3 E1 08 → 08E1
08E1: CD BB FF    CALL FFBB      ; H.LPTS 훅
08E4: DB 90       IN A,(90h)     ; 프린터 상태
08E6: 0F          RRCA
08E7: 0F          RRCA           ; bit1 → carry
08E8: 3F          CCF
08E9: 9F          SBC A,A        ; FF=ready / 00=busy
08EA: C9          RET

LPTOUT 00A5 → 08BA: ... CALL 0564(BREAKX) / CALL 08E1 / JR Z,08BE  ← busy면 무한 대기
```

- 탈출 조건: **포트 90h bit1 = 0**. openMSX 실행값 **0x00**(ready)
- 미디코드면 FFh → bit1=1 → 영구 BUSY. 코어 수정 `b31724b`(90h 읽기 00h) 후 통과 확인
- 실기에서는 t=16.65초에 **단 1회** 호출되고 지나간다(프린터 검출)
- ⚠ 대조 실험: LPTSTT를 `XOR A / RET`(항상 busy)로 패치해도 **게임은 정상 진행**.
  즉 ready/busy 자체는 이 게임의 분기를 바꾸지 않는다

## 4. 관문 ② 이후 — 실기 타임라인 (좌표계)

`FS-A1ST` 기준(GT는 약 1초 늦음). S1990 reg6로 CPU 모드 판정(60=Z80, 40=R800-ROM, 00=R800-DRAM).

| t (초) | 사건 |
|---|---|
| 0.60 | CHGCPU A=01 → R800-ROM |
| 1.90 | A=00 → Z80 |
| **7.30** | **RAM 0038 ← C3** (pc=E608, Z80) — 게임 ISR 설치 시작 |
| 7.4~8.5 | CHGCPU 왕복(01/82/00/02/80) |
| 10.5 | RAM 0038 재기록 (pc=5A36/5ABE) |
| **11.86** | **CHGCPU A=81 → R800-ROM 고정** |
| 14~58 | CPU=R800-ROM, RAM 0038 = `C3 CD E6`(게임 ISR), 정상 진행 |

**RAM 0038 판정표** — 보드에서 이 3바이트만 찍으면 진행 단계가 나온다:

| 값 | 의미 |
|---|---|
| `08 D9 F5` | 부팅 초기 (t<7) |
| `C3 3C 0C` | **BIOS ISR 현역** (t≈10의 짧은 창) |
| `C3 CD E6` | **게임 ISR 설치 완료** (t≥12) |

그리고 **0x0038은 정상 플레이에서 초당 60회 실행**된다(IM1 벡터. 실측 1,798회/30초).
`0C46`은 BIOS ISR 프롤로그의 `PUSH IY`(`0038: JP 0C3C` → 레지스터 저장)이고, 게임이
자기 ISR로 갈아탄 뒤로는 **191회를 끝으로 다시 안 나온다**. 따라서
**"0038 실행 누적"이나 "pc=0C46"은 폭주 서명이 아니다.**

⚠ 0x0180(CHGCPU)에 bp를 걸면 DOS에서 그 주소가 TPA라 **게임 코드가 지나가며 오검출**
된다(A=FF/F9/77 등). 유효한 것은 A=00/01/02/80/81/82뿐.

turbo R 타이머 공칭 **3,579,545 / 14 = 255,681.8 Hz (3.911 µs/카운트)**.

카트리지 자리(C0/C8, 80~87, B8~BB, E8~EB)는 카드가 없으면 실기도 FFh이므로 채우면 안 된다.

## 6. 남은 것

- 90h 수정 후 보드는 더 진행하다 다른 곳에서 멈춤. 다만 상대 세션 계측기가 T80s 레지스터만
  읽고 있어(NextZ80 실행 중에는 잔상) **PC 값 자체가 미확정**. 프로브 수정 후 재측정 예정
- 정지 지점이 나오면 위 §4 타임라인 + RAM 0038 판정표에 얹어 좌표를 찍는다
- 세이브스테이트: `illu_st`(ST, 시작 메뉴 직전)

## 6b. S1990 R800-DRAM 모드는 배선되어 있지 않음 (2026-09-27 확인)

§3의 모드 매핑(`60=Z80, 40=R800-ROM, 00=R800-DRAM`)에서 **00, 즉 R800-DRAM만 구현이 없다.**
검증한 사실:

- `turbor.sv:180` — `assign dram = ~cpust[1]`. 모드 비트는 제대로 디코드된다.
- `msx.sv`에서 `tr_dram`을 쓰는 곳은 **두 군데뿐**: `:1484` 포트 연결(turbor가 구동)과
  `:2066`의 `dbg_watch_pc <= {use_nz, tr_r800, tr_dram, 5'd0, dbg_m38}` — **디버그 레지스터**.
  기능적으로 읽는 곳이 없다.
- `mem_ov`는 DRAM 리맵이 아니다. `turbor.sv:137`의
  `mem_ov = en & main_rom0 & ~mreq_n & ~rd_n & ov_addr`는 슬롯 0-0 페이지 0 **읽기에 바이트를
  덮어쓰는 BIOS 오버레이**이고, `chg_arm`/`get_arm`이 0x0180/0x0183에서 무장되는 CHGCPU/GETCPU
  훅이다.

실기에서 R800-DRAM은 메인 ROM을 내부 DRAM에서 실행하므로 **그 주소 공간이 쓰기 가능해진다.**
전환을 검증하는 펌웨어(ROM 영역에 한 바이트 써서 읽어보는 식)는 우리 설계에서 영원히 실패한다.

**정정(같은 날): 정지는 없었다.** 처음 이 절을 쓸 때 "fullsys가 CHGCPU 약 4 ms 뒤 7B7F에서
멈춘다"고 적었는데 틀렸다. `cpu_speed`를 고친 뒤 1500 ms를 돌리니 **그 루프는 약 570 ms 만에
빠져나온다**(1174.40 ms에 새 PC 재개, 1202.88 ms까지 7Axx–7Bxx 진행, 1500 ms 시점에 계수 루프
안에서 계속 동작 중). 그 전 런들(`swp`/`mon`/`probe`/`z80`)은 막힌 것이 아니라 **관측 창이 짧았다**(620/700/800 ms).
그 루프는 **어느 빌드에서든** 603.8 ms부터 약 1174 ms까지 돈다. `fast`가 넘어간 것은 빨라서가
아니라 1500 ms까지 돌렸기 때문이다.

(처음 이 절은 "`cpu_speed` 오류로 6배 느렸다"고 적었는데 **그것도 틀렸다.** NextZ80은 `ce_cpu`로
클럭되지 않는다 — `msx.sv:351`의 `nz_ce = r800_fast | (nz_div == 2'd0)`로 `nz_bus`를 통해 돈다.
`cpu_speed`는 T80의 `ce_cpu`와 래치된 가드 한계만 움직인다. 수정 전 `swp`/`mon800`과 수정 후
`fast`가 이벤트 단위로 동일하다.) 고정 창에서 "정지"와 "아직 진행 중"이 같은 트레이스를 낸다 —
이 문서가 그 함정에 두 번 빠진 기록으로 남긴다.

**그리고 이 루프는 DRAM 모드와 무관하다 (s19 런, 확인됨).** 650 ms까지의 S1990 전이는
`0.058 OUT(E5),40 → cpust 10`(R800-ROM, 초기 왕복), `0.064 OUT(E5),60 → cpust 11`(Z80),
`599.575 pc~0180 → cpust 10`(R800-ROM)이다. **DRAM(cpust=00)은 선택되지 않는다.**

내가 DRAM을 의심한 근거는 "046A를 A=80으로 호출"을 `din[6:5]`로 읽은 것이었는데 **그 분기가
틀렸다.** `turbor.sv:204`는 두 갈래다:

    if (chg_arm)             cpust <= (din[1:0]==0) ? 2'b11 : (din[1:0]==1) ? 2'b10 : 2'b00;
    else if (regsel == 8'd6) cpust <= din[6:5];

`chg_arm`은 0180h **fetch**에서 무장되므로(`:148`) CHGCPU 뒤의 쓰기는 첫 갈래를 타고
**`din[1:0]`**을 BIOS 규약(0=Z80, 1=R800-ROM, 2=R800-DRAM)으로 디코드한다. `din[6:5]`는 평범한
레지스터 6 쓰기에만 쓰인다. 그래서 로그의 01h가 `cpust=10`이 되는 것이 정상이다.

따라서 **미배선은 확인된 사실이고, 이 부팅이 650 ms까지 그 모드를 요청하지 않는다**는 것이
현재 경계다. 8초 런이 그 이후의 전환을 보여주면 시각을 덧붙인다. 보여주지 않으면, 지금 어떤
부팅도 도달하지 않는 **잠재 공백**이며 — DRAM 모드를 구현해 무언가 고쳐질 것이라 기대하는
사람이 먼저 알아야 할 사실이다.

어느 쪽이든 **배선이 없다는 것 자체는 확인된 사실**이고, 여기 적기 전까지 어느 문서에도
기록되어 있지 않았다.

## 7. 팩

`Panasonic FS-A1GT` / `FS-A1ST` 머신 팩을 새로 만들어 커밋·배포했다(각 RAM 변종 포함).
진짜 turbo R BIOS라 **MSXVER(002Dh)=3**이 나오므로 002Dh 강제 오버레이가 불필요하다.
자세한 슬롯 구성·대체·생략 항목은 각 XML 주석 참조.
