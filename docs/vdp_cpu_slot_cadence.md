# VDP 가 CPU 에게 VRAM 슬롯을 주는 주기 — 실기 검증됨

"CPU 가 VDP 포트를 너무 빨리 두드리면 쓰기를 잃는가?" 에 대한 정량 답이다.
2026-08-31 에 실기로 검증됐다.

## 코드에서 읽은 값

| 근거 | 사실 |
|---|---|
| `vdp_ssg.vhd:260` | `FF_EIGHTDOTSTATE` 는 `W_H_CNT(1:0)="11"` 마다 진행 = **4 clk21m 마다 한 칸** |
| `vdp_ssg.vhd:228` | `DOTSTATE` 는 `00→01→11→10`, 역시 4 clk21m 주기. 같은 `W_H_CNT` 파생이라 **위상 정렬** |
| | ⇒ EIGHTDOTSTATE 한 칸마다 `DOTSTATE="10"` 이 **정확히 한 번** |
| `vdp.vhd:1384` | 아비터는 `DOTSTATE="10"` 에서만 결정 |
| `vdp.vhd:1385` | `DRAW` ← `PREWINDOW=1 & DISP_ON=1 & EIGHTDOTSTATE 0~4` (8칸 중 **5칸**) |
| `vdp.vhd:1394` | `SPRT` ← `EIGHTDOTSTATE=101` (스프라이트 ON 일 때, **1칸**) |
| `vdp.vhd:1404` | `CPUW` ← 그 외 |

## 결론

    8도트 주기 = 8 × 4 = 32 clk21m
    표시 중·스프라이트 ON: CPU 는 EIGHTDOTSTATE 6,7 = 주기당 2슬롯(연속)
    => 최악 슬롯 간격 = 6칸 × 4 = 24 clk21m ≈ 1.1 µs

수평 블랭킹·보더에서는 `PREWINDOW=0` 이라 CPU 가 전부 가져간다(더 넉넉).

3.58 MHz 에서 1T = 6 clk21m 이므로:

| CPU 시퀀스 | 간격 | 여유 |
|---|---|---|
| `OUT (C),A` ×2 연속 | 12T = 72 clk21m | **3배** |
| `OUTI` | 16T = 96 clk21m | 4배 |
| `OTIR` | 21T = 126 clk21m | 5배 |

**즉 이 코어는 실 V9938 규격(표시 중 8 µs 최소 간격)보다 훨씬 관대하고,
규격을 위반하는 소프트도 통과한다.**

## 실기 검증 (2026-08-31)

타세션(Hi no Tori 60Hz 패치)이 만든 계측 롬으로 확인:

- 표시기간에 **12T 간격 `OUT (C),A` 쌍**을 반복 실행 → **유실 0**
- 되읽기 검증(같은 ISR 내 2회, 그리기마다 fg/bg 위상 교대로 "같은 값 위에 떨어진 유실"까지
  잡도록 설계) → **1차·2차 모두 불일치 0**
- 화면도 픽셀 단위 완전 일치(384/384)

위 24 clk21m 모델과 **완전 정합**이다.

## 이 값을 쓸 때

- "CPU 가 VDP 를 앞질러 쓰기를 잃는다" 는 가설은 **3.58 에서는 기각**된다.
  같은 주장을 다시 만나면 이 표부터 볼 것.
- 터보(≥5.37)에서는 이야기가 다르다 — 그래서 `rtl/msx.sv` 에 VDP 페이서가 있고
  `cpu_turbo` 로 게이트된다(3.58 에서는 통째로 꺼짐).

## 부수 사실

CPU 쓰기 유실이 일어난다면 증상은 **자동증가 한 번 누락 → 그 뒤 행 전체가 1바이트 밀림**이다.
유실 개수만큼 누적되므로 "행마다 다른 수평 오프셋"으로 보인다. 반대로 그런 화면을 봤다고
곧바로 유실로 단정하면 안 된다 — 실제로 이번에 그렇게 오판했고, 원인은 **팔레트 오독**이었다.
