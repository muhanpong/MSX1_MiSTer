# omsxprobe — openMSX 계측 하네스

코어 결함을 openMSX(레퍼런스)와 대조할 때 매번 다시 짜던 Tcl을 한곳에 모은 것.
**openMSX 쪽 함정이 코드에 박혀 있는 것이 이 도구의 요점**이다. 아래 함정 목록은 전부
실제로 한 번씩 당해서 잘못된 결론을 낸 적이 있는 것들이다.

## 쓰는 법

```bash
# I/O 포트 전수 census — 누가 어느 포트를 몇 번 읽고 쓰는지, 최초 접근 PC
./omsxprobe.py ports --machine Panasonic_FS-A1ST --disk game.dsk --seconds 62

# 프레임별 상·하단 빈 줄 수 (분할/래스터 회귀 판정)
./omsxprobe.py bands --state aso_probe --frames 6

# 스프라이트 픽셀 지도 (같은 프레임을 두 번 렌더해 SPD만 다르게)
./omsxprobe.py sprites --state aso_tb_06

# 임의 주소/포트 추적
./omsxprobe.py trace --state aso_probe --bp 0x6CCC 0x6D30 --rdio 0x90 --seconds 2
```

`--state`는 openMSX 세이브스테이트 이름(`~/.openMSX/savestates/`), `--machine/--disk`는
부팅부터 돌릴 때 쓴다. 부팅은 게임에 따라 60~170초(에뮬레이션 시간)가 걸리므로,
반복 계측은 **세이브스테이트에서 분기**하는 쪽이 압도적으로 싸다.

## 판정 지표

### bands — 상·하단 빈 줄
분할(split)이 있는 게임에서 "화면이 정상인가"를 색상 다양성으로 판정하면 **검게 비는
실패를 통째로 놓친다**. 실제로 ASO에서 "상단 쓰레기 색상 수"만 보다가, 보드에서 상단
25줄이 날아간 상태를 "정상"으로 분류한 적이 있다. 정상 기준은 **상단 0 / 하단 0**이다.

### sprites — SPD 토글 차분
스프라이트가 화면에 실제로 나오는지, 어느 라인에 걸리는지를 픽셀로 증명한다.
R#8 bit1(SPD)을 1로 만들어 스프라이트만 끄고 같은 프레임을 다시 렌더해 차분을 낸다.

⚠ **연속 두 프레임을 비교하면 안 된다.** 배경이 스크롤하므로 차분에 스크롤분이 섞여
"모든 라인에 스프라이트가 있다"는 거짓 결과가 나온다(실제로 한 번 그렇게 보고했다가
정정했다). 반드시 **같은 세이브스테이트를 두 번 로드**해 동일 프레임을 렌더할 것.

⚠ 게임이 매 프레임 R#8을 다시 쓰므로, SPD는 **그 쓰기 지점마다 다시 덮어써야** 한다
(`--spd-bp`, ASO는 복귀 블록 끝 0x6D9D).

### ports — I/O census
미디코드 포트는 AND 버스로 FFh가 되고, **액티브 로우 상태 비트가 "차단" 상태로 고착**
된다. 그래서 없는 포트의 실패는 조용한 오동작이 아니라 **대기 고착**으로 나타난다.
Illusion City가 프린터 상태 포트 90h에서 영구 BUSY로 멈춘 것이 그 예다.

판정은 두 단계로 거른다.
1. **그 포트가 이 기계의 기판에 붙어 있는가.** 카트리지 포트(MSX-AUDIO C0/C8, RS-232C
   80~87, 라이트펜 B8~BB, MIDI E8~EB)는 카드가 없으면 실기도 FFh다 — 채우면 오히려
   없는 장치를 있다고 말하는 꼴이 된다.
2. 기판 포트라면(프린터 90/91, 시스템 F3~F7 등) **실기가 무엇을 돌려주는가**를 재서
   그 값을 줘야 한다.

## openMSX 함정 (전부 실측으로 당한 것)

| 함정 | 증상 | 대응 |
|---|---|---|
| `after time X`는 **상대 시간** | `[machine_info time]+X`를 넘기면 X초가 아니라 "현재+X초" 뒤가 아니라 **머신시간 X초 시점**으로 해석돼 콜백이 영영 안 옴 | 그냥 `after time 3e-5 samp` |
| 콜백 문자열 안의 변수는 **예약 시점에 치환** | 로그에 초기값만 계속 찍힘 | 반드시 `proc`을 호출 |
| `loadstate`는 **디버그 상태를 지움** | 브레이크포인트·워치포인트·`after`가 전부 사라지고 머신 시간도 되돌아감 | bp는 **loadstate 뒤에** 설치 |
| throttle off + `after frame` 캡처 | 프레임 스킵으로 **같은 렌더 프레임이 반복 저장**됨 | 캡처 구간만 `set throttle on` + `minframeskip 0` + `maxframeskip 0` |
| `debug read ioports N` = **peek** | 실행된 `IN`과 값이 다를 수 있다(프린터 90h: peek FF / 실행 00) | 값이 중요하면 `IN` 다음 주소에 bp를 걸고 A를 읽을 것 |
| RTC를 호스트 시계로 시드 | 1회성 검출 경로가 **실행마다 나타났다 사라졌다** 함(90h 읽기: 7회 중 2회) | "1회 관측"은 하한으로만 읽고, 없다고 단정하지 말 것 |
| `get_screen`은 텍스트 모드 전용 | 그래픽 모드에서 빈 문자열 | 스크린샷 + 픽셀 분석 |
| `screenshot -raw` | 빈 화면 | 일반 `screenshot` |
| `set renderer SDL` | 값 자체가 없음(최신 openMSX) | 렌더러를 건드리지 말 것 |
| 0x0180(CHGCPU)에 bp | DOS에서 그 주소는 TPA(RAM)라 **게임 코드가 지나가며 오검출** | A 값이 00/01/02/80/81/82인 것만 유효 |
| `pkill -f <패턴>` | 자기 셸을 죽임 | `pkill -x openmsx` |

## 산출물 해석 메모

- 캡처는 320×240 프레임버퍼를 확대한 것이다. **212라인 화면의 상단 보더는 14행**이므로
  `bands`/`sprites`가 말하는 행 0~13은 보더(또는 게임이 오버스캔으로 밀어 넣은 구간)다.
- openMSX 창이 240라인이라 그보다 넓은 오버스캔은 **창 밖으로 잘린다**. 오버스캔 전 구간의
  정답표는 이 도구로 만들 수 없다.
