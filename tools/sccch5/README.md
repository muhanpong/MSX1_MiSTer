# SCCCH5 — SCC+ ch5 실기 테스트 (D5)

`docs/TODO_scc_divergences.md` **D5**를 실기에서 닫기 위한 도구다.

## 무엇을 보는가

D5 결함은 `scc_mode`가 **매퍼 항**(bank3 bit7)을 **칩 모드**에 섞은 것이었다.
재생 중 bit7 없는 뱅크를 `0xA000~0xBFFF`에 페이징하면 칩이 Compatible로 떨어지고,
IKASCC는 그 순간부터 **ch5 파형을 ch4의 공유 RAM에서** 래치한다
(`IKASCC_player_s.v` `sccp_ch5_indep`) — ch5가 ch4의 미러가 된다.

판정을 **음색 비교가 아니라 소리 있음/없음**으로 만들었다:

| | |
|---|---|
| ch4 파형 | **전부 0x00 (무음)** |
| ch5 파형 | 구형파 ±100, 약 437 Hz |
| ch1 | 같은 구형파 한 옥타브 아래(약 218 Hz) = **"아직 돌고 있다" 기준음** |

    1단계 (3초)  창 OPEN    -> 낮은 드론 + 높은 톤
    2단계 (6초)  창 CLOSED  -> 둘 다 계속 나야 한다

**드론은 계속 나는데 높은 톤만 사라지면 = 결함 있음.**

## 쓰는 법

1. OSD에서 **SLOT A 또는 B = SCC+** 로 두고 그 슬롯에 ROM을 하나 로드한다
   (SCC+는 ROM_RAM 128KB 카트라 ROM이 있어야 슬롯이 산다).
2. `SCCCH5.DSK`를 마운트하고 부팅한다. AUTOEXEC이 알아서 실행한다.
3. 9초간 듣는다.

슬롯은 자동 탐색한다 — 확장 슬롯 포함 전 슬롯을 훑으며, Plus 모드로 켠 뒤
**ch5 전용 RAM**(`0xB880`)에 패턴을 쓰고 되읽어 확인하고, 창을 닫아 값이
바뀌는지까지 봐서 단순 RAM 카트와 구분한다.

## 대조군 `SCCCH5N.DSK`

같은 프로그램이되 2단계에서 **모드 레지스터로 칩을 진짜 Compatible로 내린다.**
우리 코어에서는 **높은 톤이 사라져야 정상**이다. 사라지지 않으면 측정 자체가
둔한 것이므로 본 테스트 결과도 믿을 수 없다.

> ⚠️ **openMSX에서는 이 대조군이 동작하지 않는다.** openMSX는 `SCC::writeWave`가
> mode != Plus일 때 wave4를 wave5로 **복사**하는 방식이라, 모드만 바꾸고 파형 쓰기를
> 하지 않으면 ch5가 옛 파형을 유지한다. 우리 IKASCC는 `sccp_ch5_indep`가 래치 소스를
> **연속 게이팅**해서 모드 전환 즉시 미러가 된다(실칩 하드웨어 먹스에 가까움).
> 즉 이 대조군은 **우리 코어 전용**이고, 동시에 openMSX와의 알려진 차이 하나를 드러낸다.

## 검증 상태

- openMSX(FS-A1WX + `-ext scc+`)에서 완주 확인. 녹음 분석으로 9초 내내
  218 Hz·437 Hz 두 성분이 **일정하게 유지**됨 (창 닫는 순간 포함).
- 프로그램 바이트는 역어셈블 전량 대조로 확인했다(어셈블러 없이 파이썬으로 조립).

## 빌드

```bash
python3 build_sccch5.py SCCCH5.COM            # 본 테스트
python3 build_sccch5.py --negctl SCCCH5N.COM  # 대조군
python3 ../mkdsk/mkmsxdsk.py SCCCH5.DSK --label SCCCH5 --dos1-only \
        --autoexec "SCCCH5" SCCCH5.COM
```

절대 점프만 쓴다 — 상대 점프 오프셋 계산 실수를 원천 차단하기 위해서다.
타이밍은 VDP vblank 폴링이라 **OSD CPU 속도와 무관**하다.

## 주의

슬롯 탐색 중 모든 슬롯의 `0xBFFE`(모드 레지스터)와 `0xB000`(뱅크3)에 쓴다.
SCC 계열이 아닌 카트가 꽂혀 있으면 그 매퍼를 건드릴 수 있다. 진단 도구라
감수하는 범위이고, 끝나면 페이지 2를 원래 RAM 슬롯으로 되돌린다.
