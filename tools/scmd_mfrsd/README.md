# ⚠️ 사용 비권고 — 기록 보존용

여기 있는 것들은 **"MFRSD에서 SCMD가 SCC+를 검출하게 만든다"** 는 목표로 만들었다가
**목표 자체가 틀렸음이 밝혀진** 산출물이다. **동작하지 않는다. 쓰지 말 것.**

전말: `docs/mfrsd_scc_sound_cartridge_20260823.md`

## 왜 틀렸나

SCMD는 코나미 SCC+ **사운드 카트리지**의 64/128KB 쓰기가능 RAM을 요구하고,
그 RAM에 곡 데이터를 실제로 적재해 재생한다(위 문서 §5).
MFRSD 서브슬롯 1에는 그런 RAM이 없다 — 플래시뿐이다.
게다가 SCC-I는 서브슬롯 1, 512K RAM은 서브슬롯 2에 있어 **같은 서브슬롯이 아니다**(§3, §6-2).

**레지스터를 어떻게 세팅해도 검출은 통과할 수 없고, 통과시켜도 재생할 데이터가 없다.**
실기 MFRSD에서도 동일하게 실패한다 — openMSX 자체 MFRSD 모델로 재현 확인(§9).

## 올바른 방법

**OSD에서 `SLOT A` 또는 `SLOT B` 를 `SCC+` 로 선택한다.**

`CART_TYP_SCC2`가 128KB 쓰기가능 RAM + SCC-I + **비확장 슬롯**을 제공한다
(`memory_upload.sv:661`). 실기 코나미 사운드 카트리지와 두 축 모두 일치한다.
RTL 수정도, 패치 파일도 필요 없다.

## 파일

| 파일 | 상태 |
|---|---|
| `CORE2P.SYS` | ❌ **이중으로 무효.** ① 스텁을 파일 오프셋 `0x7BA8`에 넣고 `CALL 0x7BA8`로 불렀는데, `CORE2.SYS`는 `0x0300`에 로드되므로 실제 주소는 `0x7EA8` — **0x300 어긋남**. ② 고쳐도 무의미: 패치 지점(`0x4A77`/`0x4A90`)은 플레이어 init인데 드라이버가 그 전에 `0x4068: JP 0x0000`으로 중단한다. |
| `SCMD110A_MFRSD.DSK` | ❌ 위 `CORE2P.SYS`가 들어간 디스크 이미지. 동작하지 않는다. |
| `SCMD110A_original.DSK` | ⭕ 손대지 않은 원본. 비교 기준으로만 쓸 것. |
| `MFRSDSCC.BAS` | ❌ BASIC POKE로 `mapperReg=0` / `0xBFFE=0x20` 세팅. **RAM이 생기지 않으므로 무효.** 실기 확인 완료("basic 해도 검출 안되네"). |
| `SLOTSCAN.BAS` | ⭕ 슬롯/서브슬롯 스캔 유틸리티. 이 건과 무관하게 **쓸 만하다.** |

`.DSK`/`.SYS`는 상용 소프트웨어에서 파생된 것이라 저장소에 커밋하지 않는다.
로컬에만 둔다 — 원본 일습은 `~/msx_archive/mfrsd_scmd_20260823/binaries/`.
